API GUIDES & PYTHON EXAMPLES

Build with headlessbob

Run Bob tasks from Python, connect a conversation UI, stream replies and download generated files. This guide covers the REST thread API and the text-based ACP 0.2.0 API on the same service.

Get started

You need Python 3.10 or newer, the service URL and a service access token. The Python examples use only the standard library. A Bob API key is configured on the server; it is not the token used by API clients.

export HEADLESSBOB_URL='http://127.0.0.1:8000'
export HEADLESSBOB_TOKEN='your-service-access-token'

For a deployed service, replace the URL with its HTTPS origin, without /api/v1. Running task examples consumes Bob credit and leaves the resulting threads, runs and files on the service.

Both APIs use Authorization: Bearer TOKEN. ACP is for CLI/server clients and rejects browser Origin requests. The REST wrapper accepts same-origin browser requests.

REST: create a thread and send a message

A thread holds a conversation and one Bob workspace. Each message starts a run. The shared helper reads the URL/token from your environment and reports HTTP errors.

from uuid import uuid4
from client import api, wait_run, show_result

thread = api('/api/v1/threads', {'title': 'My Python task'})
accepted = api(
    f"/api/v1/threads/{thread['id']}/messages",
    {'content': 'Create hello.txt containing Hello from Python.'},
    headers={'Idempotency-Key': str(uuid4())},
)
run = wait_run(f"/api/v1/runs/{accepted['run']['run_id']}")
show_result(run)
print('Thread:', thread['id'])

Reuse the same idempotency key when retrying the same send. A new key starts a new message. Only one run can be active in a thread.

python3 rest.py 'Explain the file you created.' --thread THREAD_ID

The full sample streams the reply, reads message history, lists files and optionally downloads one. Run and assistant-message responses include usage when Bob reports statistics.

ACP: discover Bob and execute a task

from client import api, wait_run, show_result

print(api('/agents'))
run = api('/runs', {
    'agent_name': 'headlessbob',
    'mode': 'async',
    'input': [{'role': 'user', 'parts': [{
        'content_type': 'text/plain',
        'content': 'Reply with a short hello.',
    }]}],
})
run = wait_run(f"/runs/{run['run_id']}")
show_result(run)
print('Session:', run['session_id'])

sync waits for a terminal result (HTTP 200), async returns immediately (HTTP 202), and stream returns live SSE (HTTP 200). Supply a valid previous session_id to continue the task.

python3 acp.py 'Reply briefly.' --mode sync
python3 acp.py 'Continue the previous task.' --session SESSION_ID

Streaming and cancellation

python3 acp.py 'Explain your capabilities.' --mode stream
python3 rest.py 'Create a short project README.'

Both samples print run IDs. In another terminal, stop an active task using either cancellation API:

python3 cancel.py RUN_ID --api rest
python3 cancel.py RUN_ID --api acp

The cancellation request returns HTTP 202; the sample polls for the terminal status. Closing a client, pressing Ctrl+C or reaching a client timeout does not cancel the server-side run.

ACP GET /runs/{id}/events returns stored events as JSON. The REST events endpoint streams SSE and supports replay via Last-Event-ID. The small Python samples consume one stream; production clients should add replay/reconnection handling.

Workspace files

REST threads support file browsing and authenticated downloads after active execution ends.

from client import api

files = api('/api/v1/threads/THREAD_ID/files')
for item in files['items']:
    print(item['path'], item['type'], item['downloadable'])
python3 rest.py 'Create report.txt with a short summary.' \
  --download report.txt --output report.txt

The sample refuses to overwrite an existing local file. Downloads are attachments, limited to 25 MiB per file. Hidden files, symlinks, hard links and traversal paths are excluded. HTML artifacts can be opened locally after download.

GET, PATCH, DELETE /api/v1/threads/{id}Read, rename/archive/restore or delete
GET, POST /api/v1/threads/{id}/messagesRead history or send a message
GET /api/v1/runs/{id}Run status, output and usage
GET /api/v1/runs/{id}/eventsLive SSE with replay
POST /api/v1/runs/{id}/cancelRequest cancellation
GET /api/v1/threads/{id}/filesBrowse a workspace folder with ?path=
GET /api/v1/threads/{id}/files/downloadDownload the file specified by ?path=

Archive is reversible. Delete removes the wrapper thread and messages, while run audit records and workspace files remain retained. Neither action is allowed to interrupt an active run; cancel or wait first.

Errors and limits

REST errors use {"error":{"code":"…","message":"…"}}. ACP errors use {"code":"…","message":"…","data":{…}}. Common statuses:

StatusAction
400Check the payload or unsupported input
401Check the service token
404Check the resource ID and caller ownership
409Check active runs, session recovery or archived state
413Reduce request or file size
429Wait for service capacity before retrying

Use this service with trusted operators: Bob can execute shell commands. ACP supports inline plain text only; imported sessions, Await/resume, multimodal input and ACP artifact transfer are not supported. Failed or cancelled sessions may need a fresh thread/session.
