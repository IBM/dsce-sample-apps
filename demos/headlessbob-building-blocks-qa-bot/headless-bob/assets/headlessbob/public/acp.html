ACP API

headlessbob implements the text subset of Agent Communication Protocol (ACP) 0.2.0. ACP is available at root-level routes on this service. The thread-oriented REST API uses /api/v1. Both share the same Bob runtime and run manager.

Authentication and discovery

Use the service access token from AUTH_TOKENS, not the Bob API key. These endpoints support server and CLI clients. Requests carrying a browser Origin header are rejected. Use this site's origin as BASE, or the local address below.

BASE=http://127.0.0.1:8000
# Set TOKEN to your service access token.
curl -H "Authorization: Bearer $TOKEN" "$BASE/agents"
curl -H "Authorization: Bearer $TOKEN" "$BASE/agents/headlessbob"

Run a task

curl -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' "$BASE/runs" -d '{
    "agent_name": "headlessbob",
    "input": [{"role":"user","parts":[{"content_type":"text/plain","content":"Reply hello."}]}],
    "mode": "async"
  }'

The response includes run_id, session_id and status. Use those returned IDs in the requests below. Optional usage statistics appear when Bob reports them.

ModeResponse
sync (default)HTTP 200 JSON after the run terminates. Check status for completed, failed or cancelled.
asyncHTTP 202 JSON immediately; poll the run endpoint.
streamHTTP 200 text/event-stream with ACP JSON events in data records. Use curl -N.
curl -H "Authorization: Bearer $TOKEN" "$BASE/runs/$RUN_ID"
curl -H "Authorization: Bearer $TOKEN" "$BASE/runs/$RUN_ID/events"
curl -X POST -H "Authorization: Bearer $TOKEN" "$BASE/runs/$RUN_ID/cancel"

The events endpoint returns JSON containing stored events; it is not a live SSE stream. For live output, create a run with mode: "stream". Disconnecting does not cancel execution. Cancellation returns HTTP 202; poll until the run reaches a terminal status.

Live streaming

curl -N -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' "$BASE/runs" -d '{
    "agent_name":"headlessbob",
    "input":[{"role":"user","parts":[{"content_type":"text/plain","content":"Explain this task briefly."}]}],
    "mode":"stream"
  }'

Continue a session

Use the session_id returned by a completed run. Continuation must be enabled and the session must remain usable. A failed or cancelled execution may require a new session.

curl -H "Authorization: Bearer $TOKEN" "$BASE/session/$SESSION_ID"
curl -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' "$BASE/runs" -d "{
    \"agent_name\":\"headlessbob\",
    \"session_id\":\"$SESSION_ID\",
    \"input\":[{\"role\":\"user\",\"parts\":[{\"content_type\":\"text/plain\",\"content\":\"Continue the previous task.\"}]}],
    \"mode\":\"async\"
  }"

Errors and limits

ACP errors use {"code":"invalid_input","message":"…","data":{"reason":"…"}}; data is optional. Common HTTP statuses are 400 for invalid or unsupported input, 401 for missing/invalid credentials, 403 for browser Origin requests, 404 for unavailable or unowned resources, 409 for conflicting session state, and 429 for capacity limits.

Only inline plain text is supported. ACP Await/resume (POST to an existing run), imported sessions, multimodal input, ACP artifact transfer and A2A are not implemented. Direct ACP runs do not create UI threads. To use the conversation UI and file downloads, create tasks through the thread REST API. Read the agent manifest for runtime capabilities.
