Security Scan Report

Project: DSCE Agentic SOC (SOC-APP) · Next.js frontend, Express backend, Python watsonx Orchestrate tools, bootstrap script

1. Summary

The scan covered the Express server, Next.js API routes and components, Python tools, import-all.sh, Dockerfiles, environment files and npm dependencies. It was a manual code review plus npm audit. It was not a penetration test, and git history could not be checked because the folder has no .git.

Result: code-level and dependency issues were fixed. Two items still need action from the project owner: credential rotation and API authentication.

4. Required actions

  1. Rotate every credential that appeared in .env.example and .env: the WxO API key, COS API key, and Mailjet key and secret. Treat any copy of the project that was shared or zipped as exposed.
  2. Add authentication to the Express API and Next.js /api/* routes, including /api/wxo-token, before exposing the app beyond localhost.
  3. Delete apikey (3).json from the folder above the project if it is a real key. It was not opened during the scan.
  4. Re-run import-all.sh with the new MAILJET_SENDER_EMAIL and MAILJET_DEFAULT_RECIPIENTS values so the Mailjet connection receives them.

5. Remaining risks and recommendations

  • action_tools.py auto-approves every action and does not validate payload. Add a real approval step before connecting it to firewall, EDR or Active Directory systems.
  • Move the hardcoded WxO identifiers in the widget to environment variables if they should not be public.
  • Run npm audit in CI and pin the Python tool dependencies (requests, mailjet-rest and pyyaml are unpinned in tools/requirements.txt).
  • Initialise version control and add a secret scanner (for example gitleaks) as a pre-commit hook.
